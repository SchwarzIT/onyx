Column grids are used to organize layouts, components, and content into structured hierarchies. This structure ensures consistent alignment and distribution across all views. Built on responsive breakpoints, the grid adapts smoothly from mobile screens to ultrawide monitors.



<image-card src="/images/grid-visualization.svg" alt="Visualization of the grid system using columns, gutters and margins"></image-card>

## Grid

The grid system consists of three core building blocks:

<steps>

::step
#headline
Columns

#default
Available width is divided into up to 12 columns. Elements define how many columns they span, and overflowing elements wrap to the next row.

Maximum columns adapt dynamically based on the active breakpoint. See [breakpoints](#breakpoints) below for details.
::

::step
#headline
Gutters / Gaps

#default
Elements within the grid are separated by predefined gutter spacing.
::

::step
#headline
Margins

#default
Unified outer margins provide dynamic padding around grid containers, keeping content properly indented from viewport edges.
::

</steps>

### Usage

::content-tabs
#dev
Add the `onyx-grid` CSS class to create a grid container. Use column-span classes on child elements to control sizing:

<steps>

  ::step
  #headline
  Specific number of columns

  #default
  Use `onyx-grid-span-<number>` to span a fixed number of columns:


  ```vue [Simple grid span]
  <template>
    <div class="onyx-grid">
      <OnyxCard class="onyx-grid-span-4">Grid element</OnyxCard>
    </div>
  </template>
  ```
  ::

  ::step
  #headline
  Full width

  #default
  Use `onyx-grid-span-full` to span all available columns across any breakpoint:


  ```vue [Full width grid span]
  <template>
    <div class="onyx-grid">
      <OnyxCard class="onyx-grid-span-full">Grid element</OnyxCard>
    </div>
  </template>
  ```
  ::

  ::step
  #headline
  Specific breakpoints

  #default
  To adjust column span at specific breakpoints, use `onyx-grid-<breakpoint>-span-<number>`. The element will span `<number>` of columns for that `<breakpoint>` **and larger**.

  Combine breakpoint-specific classes with a base `onyx-grid-span-<number>` class:


  ```vue [Breakpoint specific grid span]
  <template>
    <div class="onyx-grid">
      <OnyxCard class="onyx-grid-span-4 onyx-grid-md-span-6">
        <!-- Spans 4 columns below md, 6 columns at md and above -->
        Grid element
      </OnyxCard>
    </div>
  </template>
  ```
  ::

  ::step
  #headline
  Custom container

  #default
  The grid system is built on [CSS container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries). Each grid evaluates breakpoints relative to its nearest container ancestor.

  [OnyxPageLayout](/components/layouts/page-layout), [OnyxAppLayout](/components/layouts/app-layout), and [OnyxSidebar](/components/navigation/sidebar) set up container queries automatically.

  To create a custom container, set the [container-type](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/container-type) CSS property. This is useful when nesting grids inside [OnyxModal](/components/feedback/modal#grid) or custom widgets:

  ```vue
  <script lang="ts" setup>
  import { OnyxModal } from "sit-onyx";
  </script>

  <template>
    <OnyxModal class="modal" label="Example grid modal">
      <div class="onyx-grid">
        <div class="onyx-grid-span-2">Grid element</div>
      </div>
    </OnyxModal>
  </template>

  <style lang="scss" scoped>
  .modal {
    width: 32rem;
    container-type: inline-size;
  }
  </style>
  ```
  ::

</steps>

#### Grid margin

Outer grid margins are applied automatically by [OnyxPageLayout](/components/layouts/page-layout). To apply them manually, use the `.onyx-grid-layout` utility class:

```vue [Manually apply grid margin]
<template>
  <OnyxPageLayout no-padding>
    <!-- full-width section (e.g. hero) -->

    <div class="onyx-grid-layout">
      <!-- page content with standard padding -->
    </div>
  </OnyxPageLayout>
</template>
```

### Customization

Customize grid behavior by setting utility classes on the root application element:

<steps>

::step
#headline
Max width

#default
By default, the grid expands across the full viewport width. To preserve readability on wide displays (e.g. 1440px or 1920px+), limit content width using max-width utility classes. Components like OnyxNavBar and OnyxBottomBar adapt automatically.

Apply one of the following classes:

  items:
    - label: Max. width
      value: none
    - label: CSS class
      value: none (default)

  ::

  ::details-card
  ---
  name: md
  items:
    - label: Max. width
      value: 1440px
    - label: CSS class
      value: onyx-grid-max-md
      copy: true
  ---
  ::

  ::details-card

    - label: Max. width
      value: 1920px
    - label: CSS class
      value: onyx-grid-max-lg
      copy: true
  ---
  ::

</div>

::

::step

Alignment

#default

The minimum supported viewport width is 320px. Screens narrower than 320px are not officially supported.

### Usage

::content-tabs
#dev
In custom layouts or components, use SCSS mixins to query screen or container widths:

<steps>

  ::step
  #headline
  Media queries

  #default
  To apply styles based on the **viewport width**, use the `breakpoints.screen()` SCSS mixin:

  ```scss [Apply styles for screen breakpoint]
  @use "sit-onyx/breakpoints.scss";

  .some-class {
    @include breakpoints.screen(max, sm) {
      // styles for sm screens and smaller
    }

    @include breakpoints.screen(min, md) {
      // styles for md screens and larger
    }
  }
  ```

  ::

  ::step
  #headline
  Container queries

  #default
  To apply styles based on the **parent element width**, use the `breakpoints.container()` SCSS mixin. Ensure the element has `container-type` defined.

  When defining both min and max for the same breakpoint, include an offset parameter:

  ```scss [Apply styles for container breakpoint]
  @use "sit-onyx/breakpoints.scss";

  .some-class {
    container-type: size;

    @include breakpoints.container(max, md) {
      // styles for md containers and smaller
    }

    @include breakpoints.container(min, md, $offset: 1) {
      // styles for containers larger than md
    }
  }
  ```

  ::

  ::step
  #headline
  Usage in code

  #default
  To access breakpoint values in TypeScript or JavaScript, import `ONYX_BREAKPOINTS`:

  ```ts [Using breakpoints programmatically]
  import { ONYX_BREAKPOINTS } from "sit-onyx";

  console.log(`Width for sm breakpoint is: ${ONYX_BREAKPOINTS.sm}px`);
  ```

  ::

</steps>
