## Core principles

Every layout should adhere to two fundamental rules:

<steps>

::step
#headline
Responsive

#default
Layouts must adapt seamlessly across screen sizes and device types.
::

::step
#headline
Content-driven

#default
Layout is determined by content requirements. Prioritize information architecture before selecting layout patterns.
::

</steps>

Use our [grid system](/docs/foundation/breakpoints-and-grid) to ensure consistent alignment and spacing.

## Page anatomy

Standard applications are structured around four distinct layout regions:

<layout-container>
<steps>

::step
#headline
Main navigation

#default
Persistent top or left bar providing global routing and system controls. See [OnyxNavBar](/components/navigation/nav-bar).
::

::step
#headline
Sidebar

#default
Side panel for master-detail views, sub-navigation, or filtering. Stays pinned to the left or right screen edge. See [OnyxSidebar](/components/navigation/sidebar).
::

::step
#headline
Page content

#default
Primary content viewport governed by the [grid system](/docs/foundation/breakpoints-and-grid) and active scroll container. See [OnyxPageLayout](/components/layouts/page-layout).
::

::step
#headline
Bottom bar

#default
Pinned footer area for action buttons, status indicators, and batch operations. See [OnyxBottomBar](/components/navigation/bottom-bar).
::

</steps>

#dev
Use [OnyxAppLayout](/components/layouts/app-layout) and [OnyxPageLayout](/components/layouts/page-layout) to assemble the application frame:

```vue [Basic app layout]
<script lang="ts" setup>
import { OnyxAppLayout, OnyxPageLayout, OnyxNavBar, OnyxNavItem } from "sit-onyx";
</script>

<template>
  <OnyxAppLayout>
    <template #navBar>
      <OnyxNavBar app-name="App name" logo-url="/logo.svg">
        <OnyxNavItem label="Home" link="/" />
      </OnyxNavBar>
    </template>

    <OnyxPageLayout> Page content... </OnyxPageLayout>
  </OnyxAppLayout>
</template>
```

## Component layout

Internal component content is left-aligned. Center or right alignment is reserved for specialized cases, such as numeric table columns.

<layout-container>

::image-do-dont-card{color="success"}
Left-align content within components.

#image

::

::image-do-dont-card{color="danger"}
Do not center- or right-align component content, except in numeric table cells.

## Visual rhythm & Grouping

Structure interfaces by clustering related elements:

<steps>

::step
#headline
Proportion & balance

#default
Keep consistent proportions across sections to avoid visual imbalance.
::

::step
#headline
Spatial grouping

#default
Group functionally related elements together. Use white space, typography, and dividers to distinguish logical blocks and minimize cognitive load.
::

</steps>
